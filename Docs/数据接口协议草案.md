# 教室环境监测数据接口协议草案

文档版本：0.1  
日期：2026 年 10 月 16 日  
状态：保留首次实现的设计草案；当前软件服务已实现，具体行为以源码和联调记录为准  
目标网络协议：v1

## 1 设计目标

虚拟节点先实现本协议，后续 STM32F103C8T6 与 ESP8266 通过适配层实现同样的网络行为。后端与网页不根据上传端的开发语言切换接口。当前默认一个教室、一个设备、每 2000 毫秒一次采样上传。

文档版本与网络协议版本分开维护。首次实现时冻结 v1 的字段、单位、去重和确认规则；字段语义或必填结构发生不兼容变化时另起网络协议主版本。

## 2 MQTT 传输

| 项目 | 约定 |
| --- | --- |
| Broker | server 内嵌 Aedes，默认 `mqtt://127.0.0.1:1883` |
| MQTT 版本 | 3.1.1 |
| 字符编码 | UTF-8，JSON 对象，每条采样一条消息 |
| 上传周期 | 默认 2000 ms，可配置 |
| telemetry 与 ack | QoS 1，retain 为 false |
| status | QoS 1，retain 为 true，可配合遗嘱消息 |
| 上传负载上限 | JSON 负载 1024 字节，不含 MQTT 固定头、主题和报文标识 |
| 设备 ID | 1 至 64 字符，小写字母、数字、连字符 |
| 默认设备 | `classroom-001-node-001` |
| 默认教室 | `classroom-001` |

未来 ESP8266 的 MQTT 库须满足所选 QoS 和完整报文缓冲区要求。1024 字节只是应用负载预算，设备侧完整 MQTT 缓冲区还必须容纳主题与协议开销。

| 主题 | 发布方 | 订阅方 | 用途 |
| --- | --- | --- | --- |
| `envmon/v1/devices/{device_id}/telemetry` | 虚拟节点或 ESP8266 | 后端接入模块 | 环境采样 |
| `envmon/v1/devices/{device_id}/ack` | 后端 | 对应设备 | 入库结果 |
| `envmon/v1/devices/{device_id}/status` | 设备或遗嘱 | 后端 | 在线与离线提示 |

后端校验主题中的设备 ID 与消息中的 `device_id`，同时核对设备登记的教室归属。上传主题不接受 retained telemetry。status 只表示连接提示，最新数据是否过期另行判断；后端也结合实际连接和接收时间维护设备状态。

首版本机无账号模式不等于开放公网 Broker。未来接入局域网硬件时，增加设备凭据与主题访问控制；网页继续通过 HTTP 接口访问，不直接连接 MQTT。

## 3 上传 JSON

对应 Schema 为 [telemetry.schema.json](contracts/telemetry.schema.json)，完整样例为 [telemetry.example.json](contracts/telemetry.example.json)。排版后的示例如下，实际发送时建议使用紧凑单行 JSON：

```json
{
  "schema_version": 1,
  "device_id": "classroom-001-node-001",
  "room_id": "classroom-001",
  "boot_id": "7c9a21f0",
  "seq": 1,
  "sampled_at": "2026-10-16T02:00:00.000Z",
  "source": "simulator",
  "metrics": {
    "temperature_c": 24.6,
    "humidity_rh": 48.2,
    "co2_ppm": 720,
    "dust_ug_m3": 28,
    "illuminance_lux": 430
  }
}
```

示例时间仅用于说明 UTC 表达方式；虚拟节点运行时使用实际采样时间。

| 字段 | 类型 | 约束与语义 |
| --- | --- | --- |
| schema_version | integer | 固定为 1 |
| device_id | string | 持久设备身份，与 MQTT 主题匹配 |
| room_id | string | 持久教室身份，与后端登记匹配 |
| boot_id | string | 8 至 32 个小写十六进制字符，同一启动批次保持不变 |
| seq | integer | 0 至 4294967295，同一启动批次内递增 |
| sampled_at | string 或 null | UTC RFC 3339 时间，结尾为 Z；未校时则为 null |
| source | string | `simulator` 或 `hardware` |
| metrics | object | 以下五个指标键均存在，缺测值为 null |
| temperature_c | number 或 null | °C；实际采集范围由后续传感器配置约束 |
| humidity_rh | number 或 null | %RH，0 至 100 |
| co2_ppm | integer 或 null | ppm，非负整数 |
| dust_ug_m3 | number 或 null | μg/m³，非负，GP2Y1010 粉尘浓度估算值 |
| illuminance_lux | number 或 null | lx，非负 |

禁止将单位拼进数值字符串，禁止用零代表缺测。JSON 不接受 NaN 或 Infinity。JSON Schema 校验以外，还需做消息字节数、主题匹配、设备登记、时间合理性和重复消息内容检查。

GP2Y1010 的输出与粉尘密度相关，本协议不设置 `pm25_ug_m3`，也不把 `dust_ug_m3` 直接映射为 PM2.5。若以后更换为可明确输出 PM2.5 的传感器，再评审增加指标或新版本，不改写既有粉尘历史数据的含义。[Sharp 官方资料](https://global.sharp/products/device/lineup/data/pdf/datasheet/gp2y1010au_e.pdf)

## 4 时间与去重

`(device_id, boot_id, seq)` 是唯一消息标识。虚拟节点使用随机启动批次；硬件阶段选择适合 MCU 的随机值或持久启动计数方案，保证批次不被重复使用。序号接近上限时开启新批次，不在同一批次内回绕。

待补传记录始终保留生成时的批次、序号和采样时间。进程重启可以为新采样创建新批次，不能改写持久队列中的旧批次。重复判断按规范化后的完整业务内容进行，忽略 JSON 字段顺序和空白；相同标识但不同内容属于冲突。

后端自行生成 `received_at` 与 `stored_at`，不能信任上传端提供服务端时间。`sampled_at` 有效时作为历史采样时间；为 null 时，存储有效查询时间 `effective_at = received_at`，同时保留 `time_quality = received_only` 标记，页面标明采样时间未知。有效设备时间对应 `time_quality = device`。

早于当前最新读数的补传消息仍可入库，但不能覆盖较新的最新读数。建议当前时刻前 10 秒内的有效采样才参与实时报警，明显超前的时间拒收并提示设备校时；具体时间容差在 M1 冻结。未知采样时间不参与宣称基于真实采样时刻的历史趋势或新鲜度判断。

## 5 应用层入库确认

MQTT PUBACK 表示协议级接收结果，并不保证应用已经写入数据库。本项目只在 SQLite 事务提交后发送入库成功确认。[OASIS MQTT 3.1.1 第 4.3.2 节](https://docs.oasis-open.org/mqtt/mqtt/v3.1.1/os/mqtt-v3.1.1-os.html)

```json
{
  "schema_version": 1,
  "device_id": "classroom-001-node-001",
  "boot_id": "7c9a21f0",
  "seq": 1,
  "status": "stored",
  "stored_at": "2026-10-16T02:00:00.080Z"
}
```

| status | 条件 | 上传端行为 |
| --- | --- | --- |
| stored | 首次有效记录已提交 | 移出持久队列 |
| duplicate | 相同标识与内容已存在 | 移出持久队列 |
| rejected | 可关联消息被永久拒收 | 移至可查看的拒收队列，显示原因 |

`duplicate` 返回原记录的 `stored_at`。`rejected` 返回 `error.code` 与 `error.message`，不带成功存储时间；代码至少包括 `INVALID_PAYLOAD`、`IDENTITY_MISMATCH`、`MESSAGE_CONFLICT`、`INVALID_TIMESTAMP`。

无法解析或缺少完整标识的输入可能无法返回可关联的拒收确认，后端记录诊断信息。正规上传端在进入本地队列前先校验自身生成的数据；外部畸形输入用于独立的拒收测试。

数据库暂不可用时保留上传端待发记录，不发送成功或永久拒收确认。默认确认超时 10 秒；重试使用退避，上限建议 30 秒，恢复后有序补传并限制并发。首版可采用每设备一条在途消息简化顺序和确认关联。

本地队列建议使用独立 SQLite outbox，先持久保存再发送，记录状态与尝试次数。正常 MQTT 重发和应用层重试统一复用消息标识。收到重复确认后再次处理应保持幂等。24 小时队列容量和满载行为见计划书。

## 6 设备状态

设备连接时发送状态，非正常断开可由 Broker 发布遗嘱。简化状态体为：

```json
{
  "schema_version": 1,
  "device_id": "classroom-001-node-001",
  "boot_id": "7c9a21f0",
  "state": "online"
}
```

`state` 为 `online` 或 `offline`。状态消息不包含可依赖的离线发生时间，后端使用实际观察时间。后端必须将 retained 状态视为提示，并结合当前连接与活跃信息处理，避免重启后把旧 online 消息直接当成当前在线事实。

网页分别显示设备连接状态、SSE 连接状态、最近收到消息的时间、最新有效采样的时间。默认 10 秒未获得新鲜数据时标记过期，保留最后一次值并标明时间，不继续显示正常实时更新动画。

## 7 REST 接口规划

这些端点尚未实现，统一前缀为 `/api/v1`，JSON 返回时间均为 UTC。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 进程、MQTT 与数据库就绪状态 |
| GET | `/rooms` | 教室列表，首版一条 |
| GET | `/devices?room_id=...` | 设备与状态列表 |
| GET | `/devices/{device_id}/latest` | 最新指标与时间质量 |
| GET | `/devices/{device_id}/measurements?start=...&end=...&limit=100&cursor=...` | 原始数据分页 |
| GET | `/devices/{device_id}/series?start=...&end=...&metric=co2_ppm&max_points=1200` | 时间聚合曲线 |
| GET | `/alarms?device_id=...&state=...&limit=100&cursor=...` | 报警分页 |
| GET | `/devices/{device_id}/thresholds` | 当前规则与版本 |
| PUT | `/devices/{device_id}/thresholds` | 校验并整体更新规则 |
| GET | `/events?device_id=...` | SSE 连接 |

时间筛选使用左闭右开区间 `[start, end)`，接受带时区的 RFC 3339 参数并统一转 UTC；拒绝非法范围。明细以有效时间和记录 ID 稳定排序，游标包含排序位置，避免相同时间记录翻页遗漏。明细 `limit` 默认 100、最大 1000；曲线最多 1200 点，返回所用桶宽和每桶有效样本数，聚合时忽略 null，空桶不能补零。

成功响应包装为 `{ "data": ... }`，分页增加 `meta`。错误响应为 `{ "error": { "code": "...", "message": "..." } }`。时间参数或阈值非法返回 400，设备不存在返回 404，依赖未就绪返回 503。暂无采样时，latest 返回 `data: null`，历史返回空列表。

阈值规则覆盖上下界、对应恢复边界和连续次数。页面完整提交时由服务端校验上下界关系及恢复区间，事务保存并增加版本；不把 null 指标视为正常，不重写已结束的报警事件。

## 8 SSE 事件规划

| event | 内容 |
| --- | --- |
| measurement.created | 已持久化的采样，包含数据库记录 ID 与时间质量 |
| device.updated | 设备状态或数据新鲜度变化 |
| alarm.changed | 报警触发或恢复 |
| thresholds.updated | 规则版本变化 |

连接使用 `text/event-stream`，约每 15 秒发送注释心跳。事件名称通过 EventSource 的命名事件监听。单页维护一条连接，测量事件按数据库 ID 去重。

SSE 只负责通知，不作为持久数据源。重连同步时先建立事件订阅并暂存到达事件，再查询最新快照及当前曲线范围，最后合并暂存事件并去重，避免快照查询与订阅之间出现空窗。历史补传不能推动实时卡片回退。浏览器重连后以 REST 恢复状态，本期不实现无限事件回放。

## 9 后续硬件接入检查

硬件阶段需验证主题、字段、单位、字节预算、时钟同步、批次唯一性、离线容量、应用确认和重启补传。GP2Y1010 的 ADC 结果、校准及滤波在硬件适配层完成，再填入本协议的统一单位字段。

串口帧、校验和、引脚、电平和 STM32 库选型本期不确定。完成硬件后，应将相同有效载荷样例分别交给虚拟节点与真实设备发送，验证入库结构一致，网页不需要为硬件另开数据接口。
